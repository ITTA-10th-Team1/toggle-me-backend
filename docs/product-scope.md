# MVP & Final Development

MVP는 최종 버전을 목표로 설계하되, 아래 MVP 열까지만 구현한다.

- 2026-11-07: MVP 구현 목표. 최종 구현은 최종안을 기준으로 한다
- 원본: Notion `Toggle Me / BE / MVP & Final Development`

## 범위

| 항목 | MVP | 최종 |
| --- | --- | --- |
| 방 | 사용자당 1개, 1층, 벽·바닥 고정 | 2층까지 (같은 구조를 위로 복제), 벽지·바닥 재질 변경 |
| 가구 | 기본 5개 고정 배치. 옷장→전신 거울, 책장→책장 달린 책상. 창문은 고정 오브젝트 | 자유 배치, 회전, 칸 단위 겹침 방지, 게임기 등 추가 가구(구매) |
| 가구 선택 | 온보딩에서 체크로 고르기, 최소 3개 (확정인지 확인 필요) | 언제든 넣고 빼기 |
| 가구 디자인 종류 | 가구당 2~3종, 시간 되면 | 3종 + 추가 |
| 아이템 | 사진 1장 필수, 카메라·갤러리(붙여넣기 제외), 메모 선택, 아이템별 공개 on/off | 책·영화·화장품은 외부 API로 불러오기 |
| 아이템 보기 | 핀보드. 칸은 정해져 있되 선은 안 보이게, 추가하면 자동 배치, 삭제하면 앞으로 당기기 | 자유 배치·크기 조절 |
| 이미지 | S3에 원본 저장, URL로 전달 | 이미지 비율 규칙은 프론트에서 논의 중 |
| 공개·소셜 | 방 on/off. 방 둘러보기는 "한번 해보죠"로 끝남 | 아이디 검색, 친구 추가, 방명록(정해진 문구·스티커) |
| AI | 해시태그 생성, 가구별 집계. 비슷한 책 추천(알라딘)은 넣고 싶다는 의견. Spring AI + GPT | 월별 mood, e커머스 연계 |
| 로그인 | 카카오, 아이디·비밀번호 자체 계정(가입 시 이메일도 입력, 가입·로그인만). 확장할 수 있는 구조 | 네이버·구글, 이메일 인증, 계정 찾기(아이디·비밀번호) |
| 마감 | 2026-11-07 MVP 발표 (디자인은 필수, 개발은 된 데까지) | — |

## 작업 우선순위

10/5 백엔드 회의에서 정한 순서다.

| 우선순위 | 범위 |
| --- | --- |
| P0 | 인증·회원 |
| P1 | 방·층·가구, 취향 아이템·외부 데이터·이미지 |
| P2 | 핀보드, 친구·방 둘러보기, 찜하기, 방명록 |

## 비즈니스 규칙

- MVP에서 사용자당 방은 1개다 ([ADR 0001](decisions/0001-room-count-per-member.md))

미결정 사항은 Notion `MVP & Final Development` 페이지의 미결정 사항 표에서 관리하고, 확정되면 이 문서와 ADR에 반영한다.
