# MVP & Final Development

MVP는 최종 버전을 목표로 설계하되, 아래 MVP 열까지만 구현한다.

- 2026-11-07: MVP 구현 목표. 최종 구현은 최종안을 기준으로 한다
- 원본: Notion `Toggle Me / BE / MVP & Final Development`

## 범위

| 항목 | MVP | 최종 |
| --- | --- | --- |
| 방 | 사용자당 1개, 1층, 벽·바닥 고정 | 2층까지 (같은 구조를 위로 복제), 벽지·바닥 재질 변경 |
| 가구 | 기본 5개 고정 배치: 화장대·거울·책상·냉장고·TV. 창문은 고정 오브젝트. 가구 기능은 거울·냉장고 2개만 구현한다. 거울 기능은 미확정(기획 변경 예정) | 자유 배치, 회전, 칸 단위 겹침 방지, 가구 종류 추가(게임기 등 구매 가구) |
| 냉장고 | 그날 먹은 음식 사진 기록. 하루 10장, 지난 날짜 가능·미래 날짜 불가, 사진마다 메모·공개 on/off, 날짜별 목록과 월별 달력. 방에 냉장고를 둔 회원만 올릴 수 있다. 다른 사람 냉장고 구경은 팔로우 이후 구현 | — |
| 가구 선택 | 온보딩에서 체크로 고르기, 최소 4개 | 언제든 넣고 빼기 |
| 가구 디자인 종류 | 가구당 2종 | 3종 + 추가 |
| 아이템 | 사진 1장 필수, 카메라·갤러리(붙여넣기 제외), 메모 선택, 아이템별 공개 on/off, 태그 0~3개(AI 추천 중 선택) | 책·영화·화장품은 외부 API로 불러오기. 도서는 알라딘 Open API 종료로 대체 API 선정 필요 |
| 아이템 보기 | 핀보드. 칸은 정해져 있되 선은 안 보이게, 추가하면 자동 배치, 삭제하면 앞으로 당기기 | 자유 배치·크기 조절 |
| 이미지 | S3 비공개 버킷에 원본 저장. 앱이 발급받은 업로드 URL로 직접 올리고, 조회는 만료되는 보기 URL로 전달. jpeg·png·heic, 10MB 이하 | 이미지 비율 규칙은 프론트에서 논의 중 |
| 공개·소셜 | 방 on/off, 단방향 팔로우. 방 둘러보기는 "한번 해보죠"로 끝남 | 닉네임·아이디 검색, 방명록(정해진 문구·스티커) |
| AI | 아이템 기록 시 사진으로 추천 태그 최대 3개 생성(사용자가 0~3개 선택), 가구별 대표 태그로 방 태그 집계. Spring AI + Gemini 3.1 Flash-Lite ([ADR 0003](decisions/0003-ai-tag-recommendation.md)). 비슷한 책 추천은 넣고 싶다는 의견(알라딘 Open API 종료로 다른 도서 API 필요) | 월별 mood, e커머스 연계. 비슷한 옷·쇼핑 추천은 거울·책상 가구 기능에서 |
| 로그인 | 카카오, 아이디·비밀번호 자체 계정(가입 시 이메일도 입력, 가입·로그인만). 확장할 수 있는 구조 | 네이버·구글, 이메일 인증, 계정 찾기(아이디·비밀번호) |
| 마감 | 2026-11-07 MVP 발표 (디자인은 필수, 개발은 된 데까지) | — |

## 작업 우선순위

10/5 백엔드 회의에서 정한 순서다.

| 우선순위 | 범위 |
| --- | --- |
| P0 | 인증·회원 |
| P1 | 방·층·가구, 취향 아이템·외부 데이터·이미지 |
| P2 | 핀보드, 팔로우·방 둘러보기, 찜하기, 방명록 |

## 비즈니스 규칙

- MVP에서 사용자당 방은 1개다 ([ADR 0001](decisions/0001-room-count-per-member.md))
- 방 태그는 가구마다 대표 태그 하나씩, 최대 켜진 가구 수만큼 보여준다
  - 공개 아이템이면서 방에 켜진 가구에 기록한 것만 센다. 내 방과 남이 보는 방이 같은 결과를 쓴다
  - 가구 안에서는 태그가 붙은 아이템 수 많은 순, 같으면 최근 아이템 순, 그것도 같으면 아이템 안에서 앞 순서
  - 최근에 기록한 가구부터 고르고, 앞 가구가 이미 고른 태그는 건너뛴다

미결정 사항은 Notion `MVP & Final Development` 페이지의 미결정 사항 표에서 관리하고, 확정되면 이 문서와 ADR에 반영한다.
